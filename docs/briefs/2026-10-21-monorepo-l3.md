# FlightDeck monorepo: contracts, checked boundaries, packages

Feature: FlightDeck monorepo up to level 3
Goal: the Go and Python servers and the clients agree through machine-read contracts, and the folder layout of 2026-10-21 cannot drift back, because checks fail when it does.
Now: `go/`, `python/`, `clients/`, `api/` exist (brief 2026-10-21-repo-layers); `api/` is prose; nothing stops `go/core` importing `net/http` or a Python core module importing FastAPI; the two servers are compared only by `scripts/go-parity`.
Direction: contracts first (OpenAPI + JSON Schema in `api/`, one conformance suite run against both servers and the `fd` CLI), then boundary checks (Go architecture test, Python import ratchet, web-client route check), then packages (Go workspace with one module per layer, a Python project manifest, one `make check`).
Constraints: the FlightDeck service (8010) and Flightdoo (`flightdeck-odoo19`) keep running from `main`; work happens on `feat/monorepo-l3` in `.worktrees/monorepo-l3` and reaches `main` only with every check green; no network services in tests; Odoo modules keep their duplicated code.
Done when: ML-1..ML-7 hold.
Not now: Bazel/Pants/Nx; per-app versions and containers; splitting the `flightdeck` Python package; generated client code (the web client is plain JavaScript); Odoo-side contract tests (they need an Odoo test run).
Refs: `docs/briefs/2026-10-21-repo-layers.md`, `api/*.md`, `scripts/go-parity/`, evidence `devtools_mcp_trace/2026-10-21-monorepo-l3/`.

## Done when

- ML-1 `api/openapi/spend.yaml` (OpenAPI 3.1) describes the routes `fd serve` serves, with each route marked `x-servers: [go, python]` or one of them; `api/openapi/python.json` is generated from the FastAPI app by a script and checked in.
- ML-2 `api/schemas/cli/` holds a JSON Schema per `fd` command output plus the error envelope; `api/schemas/spool/` holds the command, event, state and delta shapes.
- ML-3 `api/conformance/` runs with `make contracts`: the FastAPI app (TestClient, SQLite fixture) and `go/bin/fd serve` (temp ledger) answer every shared route with bodies valid against `spend.yaml`; each `fd` command's `--json` output is valid against its schema; spool files the Go runner writes in its tests' shapes are valid against the spool schemas; `python.json` is up to date.
- ML-4 Go architecture test: `go/core` imports neither `net/http`, `server`, `runner` nor `cmd`; `server` does not import `runner`; `runner` imports neither `core` nor `server`. It runs in `make go-test`.
- ML-5 Python import ratchet: modules outside `flightdeck/routers`, `flightdeck/server.py` and the listed entry points do not import `fastapi`/`starlette` or `flightdeck.routers`; today's violations are listed in a file the test reads and the list may only shrink.
- ML-6 Web-client route check: every `/api/...` path the web client calls exists in `python.json` or `spend.yaml`.
- ML-7 Packages: `go/go.work` with modules `core`, `server`, `runner`, `cmd`; `python/pyproject.toml` (metadata and dependencies from `requirements.txt`); `make check` runs Go tests (with ML-4), Python tests (with ML-5), the web build, `make contracts` (ML-3, ML-6) and `docker compose config`.

## Decisions

- Chose contracts as schema-validated tests instead of generated code, because the web client is plain JavaScript, the Python server already has pydantic-free dict responses, and a conformance suite run against both servers catches drift without a generator to maintain.
- Chose shared spend routes in `spend.yaml` with the keys both servers send as required and the extra ones optional, because the servers differ today (`rtk_savings` and `agent_hours*` are zero in Go, `subagents` only in FastAPI, `{"error"}` vs `{"detail"}`); the differences are written into the schema descriptions.
- Chose to seed the two servers separately in conformance (FastAPI from SQL rows on a temp SQLite file, `fd` by ingesting a transcript fixture into a temp ledger), because the two ledgers have different tables (`messages` vs `responses`).
- Chose to count `flightdeck.runtime` (the FastAPI app factory and lifespan) as server layer, because only `server.py` imports it; a core module importing it is a violation.
- Chose a shrink-only allowlist for the four modules that import FastAPI outside the server layer today (`agui.routes`, `systems.containers`, `systems.mcp`, `systems.skills`), because moving them is a refactor outside this brief.
- Chose `replace => ../<module>` lines beside `go.work`, because `go mod tidy` runs per module and cannot resolve unpublished internal modules otherwise; the architecture test also checks every cross-module import has a require.
- Chose to pin every path override the Python app reads to temp paths in conformance and the OpenAPI generator, because an inherited `TOKEN_AUDIT_DB_PATH` would otherwise point the tests at the real ledger (branch review).
