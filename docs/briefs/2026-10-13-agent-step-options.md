# Agent step options

Feature: Shape Agent Steps Like Agent Nodes Elsewhere
Goal: Ask Agent answers fast, can return structured data, reports what the answer cost, and fails on its error output instead of passing an error text on as the answer.
Now: the runner's `result` event carries only cost and timing; the bridge waits for the follow cron to read the answer from the transcript; Ask Agent's settings are Prompt, Time limit, Model, Thinking effort, Session Name (2026-10-13 morning).
Direction: the runner passes per-session start options (display name, output schema, tools, budget) and puts the answer, structured output and token usage on the `result` event; the bridge resumes the flow from that event; Ask Agent gains an Options section shaped after n8n, Dify and the Claude Agent SDK.
Constraints: main settings stay as the user listed them; options are optional and hidden behind their own section; chat sessions keep `dontAsk` and the runner's allowed tools (tools may only narrow); an older runner without the new event fields still works through the transcript.
Done when: Go tests pass; `flight_deck` and `flight_deck_workflow` tests pass on a copy of the live database; the container runner runs the new binary; live `flightdeck_odoo` is upgraded.
Not now: the host runner binary (restarting it stops the user's host sessions); memory by key in the panel (removed by the user); intermediate steps output.
Refs: brief 2026-10-08-agent-steps; `runner/process.go`; `odoo/flight_deck/models/chat_bridge.py`; research notes in session 70e3feaf.

## Decisions

- Chose to put `result`, `structured_output` and `usage` on the runner's `result` event because the CLI's result frame already carries them (probe 2026-10-13: `--json-schema` gives `structured_output`, and `result` holds the final text); the transcript read stays as the fallback for an older runner.
- Chose a session per set of start options (key suffix = digest of instructions, schema, tools, budget) because `--json-schema`, `--tools`, `--max-budget-usd` and the system prompt are fixed for a process; model and effort change live, so they do not split sessions.
- Chose to pass `--name` with every start because the CLI resets a session's display name on each start; the name is the FlightDeck session's name.
- Chose to mark the result of a turn the runner sends itself (`/effort`, which ends with its own result frame, probe 2026-10-13) as `command`, and to skip it in the bridge, because otherwise the effort change's reply ("Set effort level to …") answered the prompt sent after it (review finding F1).
- Chose a queue of turn kinds (prompt or command, pushed on each write, popped on each result frame) over a counter of pending commands, because `/effort` sent while a prompt is still running would otherwise mark that prompt's result as the command's; the CLI reads stdin in order and ends each line with one result (probe 2026-10-13: ALPHA, effort, BETA came back in that order and were marked right).
- Chose "" from a step to mean the runner's default and None (code flows) to keep the session's, because a session reused by a later step kept the earlier step's model while the panel said "Runner default" (F2); an effort cannot be unset, so a runner without a default effort leaves the session's level.
- Chose to fail Ask Agent on its error output when the turn ends with `is_error` (sign-in expired, cost limit), because the error text used to arrive as the answer.
- Chose three tool sets (runner's, read-only Read/Glob/Grep, none) over a free tool list, because `--tools` only narrows what the runner's permission rules allow and a free list would invite names that do not exist.
- Chose to add Max turns (`--max-turns`) because an iteration cap is an option on most platforms (n8n, Dify, Make, Agent SDK; `knowledges/integration/agent-step-shapes`); the flag is missing from `claude --help` but the parser of 2.1.278 and 2.1.296 accepts it.
- Chose not to add a fallback model, extra directories, MCP servers or allowed/denied tool rules to the step, because each one changes what the session may reach and belongs to the runner's settings, not to one step.
- Chose to keep the time limit in Odoo (the wait's timeout) because neither the CLI nor the SDK has one; only Make offers a per-step limit.
- 2026-10-14: Chose tool sets that grant both the tools and their permission (Web search, Read files, both, Runner's tools and rules, No tools; default Web search) because the container runner runs chat sessions in dontAsk with no rules, so `--tools` alone left the agent with nothing it could use ("web search is currently denied", flow 23). A step's rules are added to the runner's for that session only; only FlightDeck managers can run the step.
- 2026-10-14: Chose a step prompt for Ask Agent without Instructions instead of the chat prompt, because the chat prompt (for Zalo) says "You have no tools here", and the agent believed it.
- 2026-10-14: Chose full model IDs for the current models (Sonnet 5.5, Opus 5.5, Haiku 5.5; Fable keeps its alias) because a CLI alias means different versions per CLI (container 2.1.278: `haiku` = Haiku 4.5, host 2.1.296: Haiku 5.5); the old aliases stay as "(CLI alias)" for sessions that use them. Opus 5.5 needs Claude Code newer than the container's 2.1.278 (API 400, probe 2026-10-14).
- 2026-10-14: Chose Sonnet 5.5 as the runner field default and set both runners to it (they were on `haiku`), at the user's request.
- 2026-10-14: Chose to report a turn with `is_error` and subtype `success` (an expired sign-in) as status `error`, because "did not answer (success)" read as a contradiction.
- 2026-10-14: Chose Mode (Manual, Edit, Plan, Auto = permission modes `default`, `acceptEdits`, `plan`, `auto`; default Auto) on both agent steps, in the order Prompt, Mode, Model, Thinking effort, Session Name as asked; Time limit and its unit follow Session Name because the request did not place them. A step saved before Mode existed runs as Auto, what its panel shows; `dontAsk` stays only for the chat bridge's own callers (Zalo). Mode changes on a running session by `set_mode`, so it does not split sessions.
- 2026-10-14: Chose neutral placeholders (`={{ _json['question'] }}`, no Session Name placeholder) because the step is not tied to any outside service.
- 2026-10-14: Chose one output shape on every way out of Ask Agent and Start Session (`status` sent/waiting/answered/timeout, `answer`, `data`, `usage`, `session_id`, `chat_key`, `asked_at`, `answered_at`, `timeout_at`, `input`; empty values are present as "" or None), because the step logged its park information first and the answer later with other keys, and the next step could not tell what to expect. The parked output keeps `waiting: "agent"`, which the canvas reads to draw a step that waits outside.
- 2026-10-14 (user): Chose to add `model` and `effort` to the step's output as the names the settings show ("Opus 5.5", "Medium"), read back from the session after the send, so a step left to the runner names the model the runner picked; two keys rather than one "Opus 5.5 Medium" string so a step can use either, and `model + ' ' + effort` gives the example. Effort is None when neither the step nor the runner sets a level.
- 2026-10-14: Chose a Next step setting on Ask Agent (After the agent answers, default; Right away; key `go_on`) over a second step, because the user asked for a flag; the label is a noun phrase and its help one sentence (UX review F6); Right away sends and goes on through the same socket with status `sent`, and the Time limit shows only when the run waits. The reply row Right away leaves waiting is answered by the next result event and resumes nothing. Start Session stays for flows that use it, now with the same output; removing it from the palette is a later decision.
- 2026-10-14: Chose to show, in a run up to a step, the fields Ask Agent and Start Session give (status `not_sent`, empty answer) as their output while still giving the next step nothing, so the next step can be mapped before any real run (UX review F5); only the keys a real run gives, all empty (no prompt, no made-up chat key), so a mapping that works in a preview also works in a run (N5).
- 2026-10-14: Chose to refuse, in `fd_chat_send` itself, any permission mode outside dontAsk, default, acceptEdits, plan and auto (never bypassPermissions), after an automated security review flagged that the bridge passed the caller's mode through. Only FlightDeck managers can create or change sessions there (read-only for users), so this is defense in depth; the `allow` rules stay as given, since only managers and code flows (admin rights) reach them.
- 2026-10-14: Left the timeout socket visible with Right away (a step's sockets do not follow its settings today); it never fires there.
- 2026-10-14: Chose to label Ask Agent's main socket "done" (key `answer` kept, so connections hold) because it is also the way out of Right away.
- Chose to deploy the container runner by copying the new binary into the running container and restarting it, not by rebuilding the image, because a rebuild also reinstalls the latest claude and codex binaries.
